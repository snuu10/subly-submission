2. 공통 검증 항목
==================================================

모든 시나리오에서 다음 항목을 확인하세요.

- AI가 사용자의 의도를 올바르게 분류하는가
- 서비스명, 금액, 주기, 결제일을 정확하게 추출하는가
- 이미 제공된 정보를 다시 묻지 않는가
- 필수 정보가 없으면 추측하지 않고 한 가지 명확한 질문을 하는가
- 최종 확인 전 DB 쓰기가 발생하지 않는가
- 확인 화면에 서비스명, 금액, 주기, 결제일이 표시되는가
- 사용자가 거절하면 DB가 변경되지 않는가
- RPC가 성공한 경우에만 성공 메시지를 보여주는가
- RPC 실패를 성공처럼 안내하지 않는가
- 동일한 확인 요청을 반복해도 중복 쓰기가 발생하지 않는가
- AI 답변과 최종 DB 값이 일치하는가
- 다른 사용자의 구독을 조회·변경·삭제할 수 없는가
- 앱과 웹에서 동일한 안전 정책이 적용되는가

각 쓰기 작업은 다음 세 시점에 DB를 확인하세요.

1. 요청 직후
2. 최종 확인 직전
3. 최종 확인 후

3. 등록 테스트
==================================================

[REG-01] 정상적인 월간 구독 등록

사용자: 스포티파이 등록해줘
예상 AI: 스포티파이 구독 금액을 질문한다.
사용자: 20000원
예상 AI: 결제 주기를 질문한다.
사용자: 매달
예상 AI: 매월 결제일을 질문한다.
사용자: 15일
예상 AI: "스포티파이 월 20,000원, 매월 15일 결제로 등록할까요?"와 같은 최종 확인을 표시한다.
사용자: 등록해줘

기대 결과:
- 최종 확인 전에는 DB에 스포티파이가 없다.
- 확인 후 정확히 한 건만 등록된다.
- 서비스명, 금액 20000, 월간 주기, 결제일 15일이 정확하다.
- AI가 실제 RPC 성공 결과를 받은 뒤에만 등록 완료를 안내한다.

[REG-02] 한 문장으로 모든 정보 입력

사용자: 스포티파이 월 20000원이고 매월 10일 결제야. 등록해줘.

기대 결과:
- 이미 받은 금액, 주기, 결제일을 다시 묻지 않는다.
- 전체 등록 내용을 보여주고 최종 확인만 요청한다.
- 확인 전에는 DB 쓰기가 없다.

[REG-03] 결제일 누락

사용자: 스포티파이 월 20000원 등록해줘.

기대 결과:
- 임의의 결제일을 생성하지 않는다.
- "매월 며칠에 결제되나요?"와 같이 결제일을 질문한다.
- 사용자가 결제일을 답한 뒤 전체 내용을 다시 확인한다.

[REG-04] 후속 답변의 대화 맥락 연결

사용자: 스포티파이 20000원 등록해줘.
AI: 결제 주기를 질문한다.
사용자: 매달
AI: 결제일을 질문한다.
사용자: 20일

기대 결과:
- "매달"과 "20일"을 새 작업으로 분류하지 않는다.
- 진행 중인 스포티파이 등록 작업에 연결한다.
- 최종 확인 전에는 등록하지 않는다.

[REG-05] 등록 거절

최종 확인 화면에서 사용자: 아니, 취소할게.

기대 결과:
- DB에 아무 데이터도 추가되지 않는다.
- 대기 중인 등록 작업이 종료된다.
- 다음 일반 질문이 등록 작업에 잘못 연결되지 않는다.

[REG-06] 중복 가능성이 있는 서비스 등록

사전 조건: 넷플릭스가 이미 등록되어 있다.
사용자: 넷플릭스 월 17000원 등록해줘.

기대 결과:
- 자동으로 두 번째 구독을 추가하지 않는다.
- 기존 넷플릭스를 보여주고 별도 계정 또는 별도 구독인지 확인한다.
- 사용자가 명확하게 별도 구독이라고 확인한 경우에만 추가 절차를 진행한다.

[REG-07] 잘못된 금액

다음 문장을 각각 테스트한다.

- 스포티파이 -20000원 등록해줘.
- 스포티파이 금액은 몰라. 등록해줘.
- 스포티파이 이만원쯤 등록해줘.

기대 결과:
- 음수 또는 불명확한 금액을 저장하지 않는다.
- 정확한 금액을 질문한다.
- 0원 허용 여부는 현재 제품 정책에 따라 일관되게 처리한다.

[REG-08] 잘못된 월 결제일

사용자: 스포티파이는 매월 32일 결제야.

기대 결과:
- 32일을 저장하지 않는다.
- 허용되는 결제일을 다시 질문한다.
- 29~31일의 말일 처리 규칙이 있다면 서버 정책과 일치한다.

[REG-09] 연간 구독 등록

사용자: 어도비 연 264000원이고 매년 9월 18일에 결제돼. 등록해줘.

기대 결과:
- 월 264000원으로 잘못 해석하지 않는다.
- 연간 주기와 9월 18일을 확인 화면에 표시한다.
- 월 환산 금액을 표시한다면 LLM 계산값이 아니라 서버 계산값을 사용한다.

[REG-10] 등록 RPC 실패

안전한 테스트 환경에서 기존 방식으로 RPC 실패 또는 네트워크 실패를 재현한다. 실패 유도를 위해 운영 코드나 원격 DB를 변경하지 않는다.

기대 결과:
- DB에 불완전한 구독이 남지 않는다.
- AI가 등록 성공이라고 말하지 않는다.
- 재시도 안내가 명확하다.
- 재시도 후 중복 등록되지 않는다.

[UPD-01] 금액 변경

사용자: 넷플릭스 요금을 19000원으로 바꿔줘.

기대 AI:
"넷플릭스 요금을 월 17,000원에서 19,000원으로 변경할까요?"와 같이 변경 전후를 표시한다.

기대 결과:
- 확인 전 금액은 17000원이다.
- 확인 후에만 19000원으로 변경된다.
- 다른 필드는 바뀌지 않는다.
- 가격 이력 기능이 있다면 정확히 한 건 기록된다.

[UPD-02] 결제일 변경

사용자: 유튜브 프리미엄 결제일을 25일로 바꿔줘.

기대 결과:
- 기존 20일과 변경될 25일을 보여준다.
- 확인 후 결제일만 변경된다.
- 금액과 주기는 유지된다.

[UPD-03] 여러 필드 동시 변경

사용자: 넷플릭스를 월 22000원, 매월 18일 결제로 바꿔줘.

기대 결과:
- 변경될 모든 필드를 확인 화면에 표시한다.
- 지정하지 않은 필드는 유지한다.
- 일부 필드만 성공하는 부분 변경이 발생하지 않는다.

[UPD-04] 새 값 누락

사용자: 넷플릭스 금액 바꿔줘.

기대 결과:
- 현재 금액을 알려주고 새 금액을 질문한다.
- 임의 금액으로 변경하지 않는다.

[UPD-05] 같은 이름의 구독이 여러 개인 경우

사용자: 넷플릭스 금액 바꿔줘.

기대 결과:
- 첫 번째 검색 결과를 임의로 변경하지 않는다.
- 금액, 결제일 또는 계정 별칭을 보여주고 변경 대상을 선택하게 한다.

[UPD-06] 존재하지 않는 구독 변경

사용자: 티빙 요금을 13500원으로 바꿔줘.

기대 결과:
- 존재하지 않는 구독을 변경했다고 말하지 않는다.
- 새로 등록할 것인지 물을 수 있지만 자동 등록하지 않는다.

[UPD-07] 변경 거절

최종 확인 화면에서 사용자: 아니, 그대로 둬.

기대 결과:
- DB의 모든 값이 유지된다.
- 변경 대기 상태가 종료된다.

[UPD-08] 오래된 확인 상태 충돌

1. 앱에서 넷플릭스 변경 확인 화면까지 진행한다.
2. 웹 또는 다른 세션에서 같은 구독을 변경하거나 삭제한다.
3. 앱에서 이전 변경을 승인한다.

기대 결과:
- 오래된 값으로 최신 데이터를 덮어쓰지 않는다.
- 최신 상태가 달라졌음을 안내하고 다시 확인받는다.
- 삭제된 구독을 자동으로 되살리지 않는다.

[UPD-09] 변경 RPC 실패

기대 결과:
- 기존 값이 그대로 유지된다.
- 성공 메시지가 표시되지 않는다.
- 재시도해도 변경 이력이 중복 생성되지 않는다.

- 사용자 선택 전에는 아무 작업도 실행하지 않는다.

- 관련 사용 체크인이 현재 FK 정책대로 처리된다.
- 진행 중이던 AI 작업이 무효화된다.
- 홈 브리핑에 삭제된 구독이 다시 나타나지 않는다.
- 삭제된 구독의 이름과 금액이 재사용 가능한 공용 데이터에 남지 않는다.

[DEL-08] 삭제 RPC 실패

- 성공 메시지가 표시되지 않는다.

[DEL-09] 다른 세션에서 이미 삭제됨

1. 앱에서 삭제 확인 화면까지 진행한다.
2. 웹에서 해당 테스트 구독을 먼저 삭제한다.
3. 앱에서 기존 삭제 요청을 승인한다.

기대 결과:
- "이미 삭제되었거나 찾을 수 없습니다"와 같이 안전하게 안내한다.
- 성공 이벤트나 삭제 이력이 중복 기록되지 않는다.

6. 대화 맥락 및 보안 테스트
==================================================

[CTX-01] 등록 도중 일반 조회

사용자: 스포티파이 등록해줘.
AI: 금액을 질문한다.
사용자: 잠깐, 이번 달 총 구독료부터 알려줘.

기대 결과:
- 월간 총액 조회를 정상 처리한다.
- 스포티파이를 자동 등록하지 않는다.
- 등록 작업을 계속할지 명확하게 안내할 수 있다.

[CTX-02] 홈 브리핑 미응답 후 AI 비서 직접 사용

1. 홈 브리핑에 넷플릭스 사용 여부 질문이 표시된 상태로 둔다.
2. 홈 카드에 응답하지 않는다.
3. AI 비서를 열어 스포티파이 등록을 진행한다.

기대 결과:
- 홈 카드의 대기 상태가 등록 대화에 섞이지 않는다.
- AI 비서 등록이 정상 진행된다.
- 홈 브리핑 이벤트는 별도 상태로 유지된다.

[SEC-01] 다른 사용자 데이터 접근 차단

전용 테스트 계정 A와 B를 사용한다.

- A가 만든 구독을 B가 조회할 수 없는지 확인한다.
- B가 A의 subscription id를 추측하거나 재사용해도 변경·삭제할 수 없는지 확인한다.
- 실패 시 다른 사용자의 서비스명, 금액 등 상세 정보를 노출하지 않는지 확인한다.

[AI-01] Claude 단일 모델 확인

- 등록·변경·삭제 대화에서 Gemini endpoint 호출이 없는지 확인한다.
- Claude 응답 실패 시 RPC 쓰기가 실행되지 않는지 확인한다.
- 로그에 프롬프트 원문, 개인정보 또는 secret이 과도하게 남지 않는지 확인한다.
