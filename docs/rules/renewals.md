# 정기 구독 갱신

갱신: 2026-09-14

앱·웹·알림·AI 비서 공통. Subly는 계좌·카드 연동 없이 사용자가 등록한 일정으로 동작하므로,
**월간·연간 정기 구독은 자동 갱신되는 것으로 가정**한다.

## 기본 원칙

- `monthly`, `yearly`는 자동 갱신으로 간주한다. 등록 화면에서 자동·수동을 묻지 않는다.
- `one_time`은 갱신하지 않는다.
- 갱신일에는 `오늘 갱신 예정` 또는 `D-DAY`로 표시한다.
- 갱신일 다음 날부터 다음 회차 결제 예정일을 표시한다.
- 날짜가 지났다는 사실은 실제 결제 확인이 아니다. 앱은 `결제 완료` 대신
  `등록된 일정 기준 갱신 반영` 또는 `예상 결제`라고 표현한다.
- 영수증이나 사용자의 명시적인 입력으로 확인된 경우에만 `확인된 결제`라고 표현한다.

## 비용 반영

- 월평균 구독 지출액은 활성 정기 구독의 유지 비용이다.
- 이번 달 예상 지출액은 이번 달에 잡힌 정기·일회성 결제 일정 전체의 합계다.
- 다음 달 예상 지출액은 다음 달에 결제 일정이 있는 활성 구독의 합계다.
- 구독이 종료되면 종료일 뒤의 예상 비용에서 제외한다.
- 일정만으로 계산한 금액을 `실제 결제 총액`이라고 부르지 않는다.

## 갱신하지 않음·종료·삭제

- `갱신 안 함`은 목록 삭제로 처리하지 않는다.
- 사용자가 `갱신 안 할래`라고 말하면 실제 서비스 해지가 필요함을 알리고,
  해지 안내 또는 `종료 예정으로 기록`을 제안한다.
- 실제 서비스 해지 여부를 먼저 확인한 뒤 `종료 예정`으로 기록한다.
- 해지가 확인된 종료 예정 구독은 이용 종료일까지 목록에 유지하고, 종료일이 되면 별도 재확인 없이 `종료`로 바꾼다.
- `종료`는 이후 예상 비용에서 제외하지만 과거 기록은 보존한다.
- `목록에서 삭제`는 별도의 명시적인 삭제 동작이며, 기록과 통계가 사라짐을 확인받는다.
- Subly의 상태 변경만으로 외부 서비스의 실제 자동 결제가 중단되지는 않는다.

## 상태 필터와 액션 용어

- 앱·웹 구독 목록의 상태 필터는 `전체 상태`, `활성`, `일시정지`, `종료 예정`, `종료`를 사용한다.
- 활성 구독을 멈추는 액션은 기존과 동일하게 `일시정지`로 표시한다.
- 일시정지된 구독을 다시 활성화하는 액션은 `다시 시작`으로 표시한다.
- 목록·AI 비서의 사용자 표시 문구는 `다시 시작`으로 통일하되, AI 비서는 `재개`, `다시 켜기`도 같은 의도로 인식한다.
- `일시정지하기`는 별도 변형으로 사용하지 않는다.

## 알림과 브리핑

- D-3, D-1은 결제 예정 알림을 보낸다.
- D-Day에는 오늘 갱신 예정임을 표시한다.
- 매달 결제 여부를 묻는 D+1 푸시는 기본 제공하지 않는다.
- AI 브리핑은 이번 주 갱신 건수·예상 금액과 예외 상황을 요약한다.

## AI 비서

- 일정이 지난 구독을 실제로 결제됐다고 단정하지 않는다.
- 비용 답변에는 `등록된 일정 기준`, `예상`, `확인된 결제`를 구분한다.
- `갱신 안 함`을 바로 삭제로 실행하지 않고 해지 의도를 확인한다.
- 앱·웹과 동일한 공통 계산 결과를 사용한다.
