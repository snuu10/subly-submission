# 인증

갱신: 2026-09-14

## 보호 라우트

- 인증 전에는 온보딩만 접근할 수 있다.
- 탭, 구독 상세, 카테고리, 결제수단, 사용 기록, 비밀번호 변경, 비서, 영수증 화면은 Supabase 세션이 있을 때만 접근할 수 있다.
- 인증 상태를 복원하는 동안에는 보호 화면이나 온보딩을 먼저 렌더링하지 않는다.
- 로그아웃하거나 세션이 만료되면 보호 화면의 내비게이션 기록을 제거하고 온보딩으로 이동한다.

출처: 2026-09-12 「Supabase Auth와 보호 라우트 설정」

## 가입 초안

- 가입 **단계 안**에서 이전 칸으로 가면 수정용이므로 값을 남긴다.
- 가입을 **포기**하면(첫 단계에서 뒤로, 로그인/찾기로 나감) 이름·이메일·비밀번호·확인·인증번호를 모두 지운다.
- 다시 가입을 시작해도 비어 있어야 한다.

출처: 2026-09-05 「가입 취소·되돌아가기 후 입력이 남아 있으면 안 됨」

## 아이디·비밀번호 찾기

- 로그인 ID는 이메일이다. **아이디 찾기**는 이름을 넣어 가입 이메일을 마스킹해 보여 준다 (`qk***@gmail.com`). 여러 명이면 모두 보여 준다. 없으면 「일치하는 계정이 없습니다」.
- 원문 이메일은 클라이언트에 내려주지 않는다.
- **비밀번호 찾기**는 이메일로 **6자리 숫자**를 받은 뒤 새 비밀번호를 넣는다.
- 설정에서는 **비밀번호 변경만** 한다. 이메일(비밀번호) 계정에만 보인다. 카카오·구글만 있는 계정은 숨긴다.

출처: 2026-09-05 아이디 찾기(이름→마스킹 이메일), 비밀번호 찾기, 설정 비밀번호 변경.

## 이메일 인증번호

- 이메일 인증번호는 **6자리로 고정**한다.
- 앱·웹 문구는 **「6자리 숫자」**.
- 입력·검증도 6자리만 받는다.

출처: 2026-09-05 「인증숫자를 8자리로 고정」, 2026-09-14 「인증번호 6자리로 변경」.

## 로그인 수단

- 카카오·구글 소셜 로그인 (Supabase Auth).
- **간편인증만 있지 않고 자체 이메일 회원가입도 필요**하다.

출처: 2026-08-23 「추가로 간편인증말고 자체 회원가입도 필요해」

## 가입 폼 (앱)

- 한 화면에 필드를 하나씩만 활성화한다.
- 순서: 이름 → 이메일 → 비밀번호 → 비밀번호 확인 → 인증번호.
- 유효하면 「다음」 없이 다음 필드가 나타나고, 새 필드는 **위쪽**에 생긴다.
- 이전 필드를 탭하면 다시 수정할 수 있다.
- 마지막 필드까지 채워져야 「가입하기」가 나온다.
- 카카오/구글 버튼과 「로그인으로 전환」은 순차 폼 아래(또는 완료 후)에 남긴다.

출처: 2026-08-25 토스식 순차 가입 폼.

## 앱과 웹

- 같은 Supabase 계정이면 **구독 데이터는 공유**된다.
- **로그인 세션은 기기·브라우저마다 따로**다. 웹 로그인으로 앱이 자동 열리지 않는다.
- Google Client ID·Secret은 앱 `.env`가 아니라 **Supabase Dashboard**에만 넣는다.

출처: 2026-09-01 「앱 로그인 정보하고 웹 로그인 정보는 공유가되는거죠?」 및 접속 가이드 확정.
