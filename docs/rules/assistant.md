홈/대시보드의 브리핑 카드(앱 `components/AiBriefingCard.tsx`, 웹 위젯 id `briefing`)의 표시 이름을
**"나우 로그"**로 바꿨다. 실제 대화형 챗봇 화면(앱 `chat.tsx` 가운데 탭, 웹 `AssistantPanel.tsx`)은

그 문구·버튼 라벨(`aria-label`/`accessibilityLabel`)은 그대로 "AI 비서"를 가리킨다.

## 홈 브리핑 카드

앱을 열자마자 알아야 할 **가장 중요한 구독 정보 한 가지**만 보여준다.

다룰 수 있는 주제:

- 결제 예정
- 사용 여부 확인
- 중복 가능성
- 가격 인상
- 무료 체험·연간 갱신 임박
- 해지 진행 확인
- 월간 절약 성과

한 카드에 넣는 것:

- 핵심 사실
- 판단 근거
- 질문 한 가지
- 선택지 2~3개
- AI 비서로 이동하는 버튼

홈 카드에서 **복잡한 대화나 구독 변경을 직접 처리하지 않는다.**

## AI 비서

홈에서 시작된 질문을 이어받아 담당한다.

- 상세한 근거 설명
- 여러 구독 비교
- 예상 절약액 설명
- 자유로운 후속 질문
- 「두 번째 거」 같은 맥락 이해
- **해지 방법 안내**
- 추가·수정·삭제 **확인**
- **사용자가 승인한 작업만** 실제 반영
- 월간·연간 구독은 자동 갱신되는 것으로 가정하되 실제 결제가 확인됐다고 단정하지 않음
- 비용은 `월평균 구독 지출액`, `예상 지출액`, `확인된 결제액`을 구분
- 카테고리 질문(「카테고리 현황」「카테고리별 지출」 포함)은 목록 조회가 아니라 카테고리 분석으로 답하고,
  금액 큰 순으로 카테고리별 `금액`·`비중`·`구독 개수`와 합계를 함께 안내
- 추천 명령어 칩은 **분류 테스트로 의도가 보장된 문구만** 노출한다.
  정본은 `supabase/functions/assistant-turn/suggestions.ts`이고, 앱(`constants/assistant-suggestions.ts`)과
  웹(`web/src/lib/assistant-suggestions.ts`)은 그 복제본이다. 세 곳이 어긋나면 테스트가 실패한다.
  문구가 기대 의도로 분류되지 않으면 분류기가 아니라 문구를 바꾼다.
  확인 카드가 열려 있는 동안에는 칩을 노출하지 않는다.
- 「갱신 안 함」은 삭제로 처리하지 않고 실제 서비스 해지 의도를 확인
- 구독 이름·카테고리 이름은 오타여도 **저장된 그대로** 유지한다. 오타 허용은 오직 "찾는" 쪽에만
  적용한다 — 프리셋 카테고리 자동 배정(`matchPresetHint`), 커스텀 카테고리 조회(`findMentionedCategory`),
  구독 이름으로 수정·삭제·일시정지·다시 시작할 대상 찾기(`findByNameFuzzy`)까지 세 곳.
  정확·부분 일치가 모두 실패했을 때만 오타 허용으로 넘어가고, 결과는 항상 사용자가 탭해서 고르는
  후보로 보여준다 — 조용히 하나를 추측해 골라 반영하지 않는다.
  카테고리 조회는 후보가 하나도 안 잡히면(오타 허용까지 실패) 실제 보유 카테고리 이름을 후보로
  대신 보여준다(`category_candidates`).
- 실제 서비스 해지를 확인해 종료 예정으로 기록한 뒤에는 이용 종료일에 자동 종료하며, 종료 여부를 다시 묻지 않음

## 연결

```
푸시 → 홈 브리핑 카드 → 간단한 선택 → 비서로 구조화 맥락 전달
→ 상세 설명·후속 질문 → 확인 카드 → 실제 반영
```

비서로 넘길 때 문장만 보내지 않고 같이 넘긴다.

- 브리핑 이벤트 ID
- 질문 의도
- 대상 구독 ID
- 관련 구독 ID 목록
- 카드에 표시한 근거
- 사용자가 선택한 값
- 대기 중인 작업 ID

## 해지 vs 목록 삭제

- 「해지」「없애줘」「해지 방법」→ **실제 서비스 해지 안내**. 앱 목록 삭제가 아니다.
- 앱 목록에서 지우는 것은 「목록에서 삭제」처럼 **삭제**로만 한다.
- 앱에서 지우는 것과 실제 해지는 다르다.
- 해지 안내는 결제 경로(웹/앱스토어/플레이스토어/통신사)를 사용자에게 묻지 않고 항상 웹 결제
  기준으로 생성한다. 다른 채널로 결제했다면 카드의 고정 안내 문구로 공식 사이트·고객센터 확인을
  유도한다(2026-09-18 개편, `supabase/functions/assistant-turn/index.ts`).
- 해지 안내를 찾지 못해도(`not_found`) 삭제는 실제 해지가 아니다 — "목록에서만 지워드릴까요?"
  문구로 그 구분을 명시한 뒤 기존 "목록에서 삭제" 확인 카드로 유도한다.

## 나우 로그 카드: 우선순위 큐 (2026-09-16 개편)

홈/대시보드의 "나우 로그" 카드는 더 이상 고정된 2장(폴백+다이제스트) 구조가 아니라, 최대 3장까지
우선순위 큐로 뽑은 카드를 캐러셀로 보여준다. 우선순위·중복 제거·자동 전환 규칙은
[docs/ai-briefing-card-carousel-plan.md](../ai-briefing-card-carousel-plan.md)와
[docs/nowlog-topic-priority-decisions.md](../nowlog-topic-priority-decisions.md)에 확정되어 있고,
`lib/nowlog.ts`(앱)·`web/src/lib/nowlog.ts`(웹)에 동일하게 구현되어 있다. 아래 두 문단(웹은 인사이트 안에
배치, 앱은 첫 장 고정)은 이 개편 이전 구조라 더 이상 맞지 않는다 — 지금은 앱·웹 모두 같은
우선순위 큐(`buildNowLogCards`)로 나우 로그 카드 자체를 채운다.

## 브리핑 부가 규칙

- **주간 다이제스트**: 월요일 아침, 지난주 대비 이번 주 결제 변화를 한 줄. **AI는 주 1회만** 호출한다.
- 주간 다이제스트는 실제 결제 내역이 아니라 등록된 `billing_cycle`과 `anchor_date`를 기준으로 한
  **결제 예정 정보**라고 명시한다. 월요일에 생성하고 같은 주 화요일~일요일에는 캐시를 조회해 계속 노출한다.
- 웹에서는 `인사이트` 위젯 안에 주간 결제 브리핑을 배치하고, 오른쪽 AI 비서 카드는 다음 결제·알림 등
  기존 역할을 유지한다. 브리핑 전체를 누르면 표시 근거와 함께 AI 비서의 후속 질문으로 연결한다.
- 앱에서는 기존 AI 비서 카드를 첫 장으로 유지하고, 주간 결제 브리핑을 두 번째 장으로 둔 슬라이드형
  카드로 제공한다. 자동 슬라이드는 사용하지 않으며 기존 AI 비서 카드의 버튼과 목적을 유지한다.
- 주간 결제 브리핑은 기간 비교와 원인 탐색을, AI 비서 홈 카드는 다음 결제와 즉시 행동을 담당해
  같은 정보를 반복하지 않는다.
- **미사용 구독 리마인드**: 한동안 확인하지 않은 구독을 주 1회 브리핑 카드에 띄운다.
- **등록 시 카테고리 제안**: 서비스명을 입력하면 카테고리·아이콘을 추천하고, 사용자는 확인만 한다. (요청 당시 Gemini)
