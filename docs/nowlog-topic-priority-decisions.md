# 나우로그 토픽 구성 및 우선순위 결정안

## 결론

1. `ending_soon`은 `구독 종료 확인`과 합치지 않고 **별도 `종료 예정` 토픽**으로 둔다.
2. 같은 구독이 여러 후보에 포함되면 **상위 우선순위의 개별 카드만 노출**한다.
3. 기존 `this_week` 카드는 제거하고 **주간 브리핑에 흡수**한다.
4. 나우로그에는 우선순위가 높은 카드 **최대 3장**을 노출한다.
5. 카드가 2장 이상이면 **7초마다 자동 전환**하며 좌우 스와이프와 페이지 표시를 함께 제공한다.

## 1. `ending_soon` 처리

`ending_soon`과 `end_confirm`은 사용자에게 요구하는 행동이 다르므로 같은 슬롯으로 합치지 않는다.

- `ending_soon`: 종료 예정 사실을 미리 안내
- `end_confirm`: 실제로 종료됐는지 사용자 확인 필요

두 상태를 모두 `구독 종료 확인`으로 표시하면 아직 확인할 필요가 없는 사용자에게 확인을 요구하는 것처럼 보일 수 있다.

### 종료 예정 카드

```text
종료 예정

왓챠 이용이 3일 뒤 끝나요
종료일 9월 19일

[구독 확인하기]
```

### 종료 확인 카드

```text
종료 확인

왓챠가 실제로 종료됐나요?

[종료됐어요] [아직 결제돼요]
```

### Lifecycle 상태별 버튼

`ending_soon`에 무조건 `해지 안내` 버튼을 표시하지 않는다. 이미 해지를 신청했고 종료를 기다리는 사용자일 수 있기 때문이다.

| Lifecycle 상태 | 권장 버튼 |
|---|---|
| `guide_reviewed` | `해지 계속하기` |
| `cancel_requested` | `진행 상태 확인` |
| `ending_scheduled` | `구독 확인하기` |
| `end_confirm` | `종료됐어요` / `아직 결제돼요` |

`ending_soon`의 우선순위는 `end_confirm`보다 낮게 둔다.

## 2. 동일 구독 중복 제거

같은 구독이 여러 개별 카드에 반복되면 사용자가 서로 다른 사건으로 오해할 수 있다.

```text
밀리의서재 무료 체험 종료
밀리의서재 오늘 결제
밀리의서재 이번 주 결제
```

구독 ID를 기준으로 우선순위가 가장 높은 개별 카드만 남긴다.

```ts
const usedSubscriptionIds = new Set<string>();

for (const candidate of prioritySortedCandidates) {
  if (usedSubscriptionIds.has(candidate.subscriptionId)) continue;

  selected.push(candidate);
  usedSubscriptionIds.add(candidate.subscriptionId);

  if (selected.length === 3) break;
}
```

### 주간 합계 예외

중복 제거는 **개별 카드 노출에만 적용**한다. 주간 브리핑의 결제 건수와 예상 총액에서는 이미 개별 카드로 노출된 구독도 제외하지 않는다.

예를 들어 넷플릭스가 `오늘 결제` 카드로 노출됐더라도 주간 브리핑의 총 결제 건수와 예상 결제액에는 넷플릭스를 포함한다.

## 3. `this_week` 주간 브리핑 흡수

기존 `this_week`와 주간 브리핑은 유사한 정보를 반복하므로 별도 카드로 유지하지 않는다.

기존:

```text
이번 주 결제 예정 3건
이번 주 예상 결제액 39,700원
```

통합 후:

```text
이번 주 구독 브리핑

오늘 결제 1건
이번 주 남은 결제 2건
예상 결제액 39,700원

[내역 보기]
```

오늘 결제는 시급성이 높으므로 별도 `today_payment` 카드로 유지한다. 주간 브리핑에는 오늘 결제도 전체 통계에 포함됐음을 명확하게 표시한다.

```text
개별 카드:
오늘 결제 예정 — 넷플릭스 ₩17,000

주간 브리핑:
오늘 결제 1건 포함 · 이번 주 총 3건
예상 결제액 ₩39,700
```

## 4. 최종 토픽 우선순위

| 우선순위 | 나우로그 토픽 | 처리 방식 |
|---:|---|---|
| 1 | 종료 확인 | 별도 유지 |
| 2 | 무료 체험 D0 | 별도 유지, 복수면 한 카드로 집계 |
| 3 | 오늘 결제 | 별도 유지 |
| 4 | 종료 예정 | 별도 유지 |
| 5 | 사용 여부 확인 | 별도 유지 |
| 6 | 주간 브리핑 | 기존 `this_week` 흡수 |
| - | 기존 `this_week` | 제거 |

우선순위 후보 중 상위 3장만 나우로그에 표시한다.

## 5. 자동 전환 규칙

- 카드 1장: 자동 전환 없음
- 카드 2장 이상: 7초마다 다음 카드로 전환
- 마지막 카드 다음에는 첫 카드로 순환
- 좌우 스와이프로 직접 이동 가능
- 하단에 점 또는 `1/3` 형태의 페이지 표시 제공
- 사용자가 터치하거나 스와이프하면 자동 전환 일시정지
- 앱이 백그라운드로 이동하면 타이머 정지
- 접근성의 동작 줄이기가 활성화된 경우 자동 전환 비활성화

## 6. 무료 체험 관련 연계 규칙

- 무료 체험 종료 알림은 D-3·D-1·D0 총 3회 제공한다.
- 세 알림 모두 `trial_ending` 종류로 생성한다.
- 체험 기간에는 같은 날짜의 일반 `payment_due` 알림을 중복 생성하지 않는다.
- D0에는 나우로그의 `무료 체험 D0` 카드도 표시한다.
- 같은 날 종료되는 무료 체험이 여러 개면 카드 여러 장이 아니라 한 장으로 집계한다.
- 체험 종료 다음 날에는 D0 카드를 제거하고 일반 유료 구독 알림 체계로 전환한다.

## 7. 구현 시 검증 항목

- `ending_soon`과 `end_confirm`이 서로 다른 문구와 버튼을 사용한다.
- 동일 구독의 하위 우선순위 개별 카드가 제거된다.
- 개별 카드에서 제거된 구독도 주간 합계에는 포함된다.
- 기존 `this_week` 카드가 중복으로 남지 않는다.
- `today_payment` 카드와 주간 브리핑의 통계가 모순되지 않는다.
- 무료 체험 여러 건이 D0 카드 하나로 집계된다.
- 카드가 1장이면 자동 전환 타이머가 실행되지 않는다.
- 카드가 2장 이상이면 7초마다 순환한다.
- 사용자 스와이프, 앱 백그라운드, 동작 줄이기 설정에서 자동 전환이 정지된다.
